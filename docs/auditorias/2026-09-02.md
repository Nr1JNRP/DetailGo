## O que mudou desde a última auditoria (2026-08-26)

Comparação com o relatório anterior (`docs/auditorias/2026-08-26.md`):

- **[CORRIGIDO] Escalação de papel em `users/{userId}` (Anteriormente ALTO):**
  As `firestore.rules` foram atualizadas com a restrição `!request.resource.data.diff(resource.data).affectedKeys().hasAny(['role'])`, impedindo que um cliente comum altere seu próprio papel para `owner`.
- **[CORRIGIDO] Leitura irrestrita da coleção `/payments/{paymentId}` (Anteriormente MÉDIO):**
  A regra de leitura foi alterada para `allow read: if isShopOwner(resource.data.shopId);`, garantindo que apenas o proprietário do estabelecimento tenha acesso aos dados financeiros da sua loja.
- **[RESOLVIDO] Webhook de pagamento sem validação (Anteriormente MÉDIO):**
  A integração de pagamentos foi migrada/consolidada com o gateway Asaas (`asaasWebhook`). O endpoint agora exige e valida o cabeçalho `asaas-access-token` contra o segredo `ASAAS_WEBHOOK_TOKEN` (`isValidAsaasToken`).
- **[EM ABERTO] Endpoints de geocodificação sem autenticação Firebase (`geocode` e `reverseGeocode`) (MÉDIO):**
  Permanece sem exigência de Firebase ID Token no cabeçalho das requisições.
- **[EM ABERTO] Ausência de validação de limites nos parâmetros do proxy `reverseGeocode` (BAIXO):**
  Permanece sem validação numérica de intervalo (`-90 <= lat <= 90` e `-180 <= lng <= 180`).

## Detalhamento dos Achados

### 1. Endpoints de geocodificação sem autenticação Firebase (`geocode` e `reverseGeocode`)

- **Severidade:** MÉDIO
- **Arquivo afetado:** `functions/src/geo/geocode.ts`
- **Comportamento vulnerável:** As Cloud Functions HTTP `geocode` e `reverseGeocode` continuam públicas e não verificam o cabeçalho `Authorization: Bearer <idToken>` de um usuário autenticado no Firebase.
- **Impacto possível:** Qualquer requisição HTTP externa não autenticada pode utilizar estas funções como proxy para consultar a API do Google Maps, consumindo a cota e gerando custos associados ao segredo `GOOGLE_GEOCODING_KEY`.
- **Correção recomendada:** Adicionar a verificação do Firebase ID Token (`admin.auth().verifyIdToken(idToken)`) no início de ambas as funções HTTP, reutilizando o padrão aplicado em `createAsaasCheckout` ou `autorizarDonoDoShop`.
- **Cabe teste de regressão:** Sim. Teste unitário garantindo que chamadas sem token válido retornem status `401 Unauthorized`.

---

### 2. Ausência de validação de limites nos parâmetros do proxy `reverseGeocode`

- **Severidade:** BAIXO
- **Arquivo afetado:** `functions/src/geo/geocode.ts` (linhas 72–78)
- **Comportamento vulnerável:** A função `reverseGeocode` valida apenas se `lat` e `lng` não são nulos/indefinidos, mas não valida se são do tipo `number` dentro dos intervalos válidos (`-90 <= lat <= 90` e `-180 <= lng <= 180`).
- **Impacto possível:** Envio de dados malformados ou fora do intervalo pode causar erros na requisição upstream do Google Maps Geocoding API ou comportamento indefinido.
- **Correção recomendada:** Incluir verificação de tipo numérico e limites geográficos para os parâmetros `lat` e `lng`.
- **Cabe teste de regressão:** Sim. Teste unitário validando que requisições com coordenadas inválidas retornem `400 Bad Request`.

## Verificação das Demais Superfícies de Segurança

### A. Credenciais e Histórico do Git

- **Status:** **CONFORME (BAIXO / Sem achados)**
- **Análise:** Nenhum segredo ou chave privada foi encontrado nos arquivos da aplicação ou no histórico recente do Git. As chaves de API (`ASAAS_API_KEY`, `ASAAS_WEBHOOK_TOKEN`, `GOOGLE_GEOCODING_KEY`) são gerenciadas com segurança via Firebase Secrets Manager (`defineSecret`).

### B. Logs e Proteção de Dados Sensíveis (PII)

- **Status:** **CONFORME (BAIXO / Sem achados)**
- **Análise:** Não existem chamadas `console.log` no aplicativo. As Cloud Functions utilizam `firebase-functions/v2/logger` registrando exclusivamente identificadores de recursos (`shopId`, `appointmentId`, `paymentId`), sem expor e-mails, senhas, telefones, tokens FCM brutos ou dados de pagamento.

### C. Regras do Firestore e Storage

- **Status:** **CONFORME (BAIXO / Sem achados)**
- **Análise:** O isolamento multi-tenant está mantido nas coleções de `shops/{shopId}`. As correções das regras em `users/{userId}` e `/payments/{paymentId}` estão ativas e impedem escalação de privilégios ou leitura não autorizada. O Storage restringe uploads a imagens com menos de 5 MB dentro do caminho `users/{uid}/`.

### D. Webhooks e Pagamentos (Asaas)

- **Status:** **CONFORME (BAIXO / Sem achados)**
- **Análise:** O webhook do Asaas (`asaasWebhook`) valida adequadamente o token do cabeçalho `asaas-access-token`. O app não ativa assinaturas localmente — a atualização é realizada de forma transacional no backend pela Cloud Function após confirmação do evento.

---

## Recomendação Geral

Priorizar em uma próxima sprint a adição de autenticação via Firebase ID Token nos endpoints `geocode` e `reverseGeocode` em `functions/src/geo/geocode.ts`, eliminando a superfície de abuso público e consumo indevido de cotas do Google Maps.
